# Audit croisé OpenAPI — Groupe 3 (ThermalSense)

- **Groupe auditeur :** Groupe 1 — Kenza, Enzo, Matteo, Tommy, Valentin
- **Contrat audité :** Groupe 3 — ThermalSense (`openapi.yml`, OpenAPI 3.0.3)
- **Créneau :** 09h15–09h55
- _NB : un second spec (`swagger/v1.ts`) est servi à `/docs` et diffère du `openapi.yml` — voir incohérence._

## Grille (8 critères)

1. **Endpoint testable sans lire le code — Partiel.** Chemins, méthodes, paramètres et bodies clairs, mais **aucun bloc `servers`** (URL de base inconnue) et **aucune info d'auth** alors que l'API exige un Bearer JWT : impossible d'appeler une route protégée avec ce seul fichier.
2. **Erreurs 4xx/5xx — Partiel.** Codes présents (400/404/500), mais le corps `Error` n'est référencé que sur `POST /building` ; tout le reste n'a qu'une description.
3. **Versioning — Partiel.** `info.version: 1.0.0` présent, mais aucune stratégie : ni préfixe d'URL, ni header, ni `servers`.
4. **Exemples — Partiel.** Aucun `example` dans le `openapi.yml`, mais le README fournit des exemples curl de requêtes (login, création de bâtiment…).
5. **Cohérence des schemas — Partiel.** Schémas lisibles, mais aucun `required`, aucun `format` (les `id` sont des `string` nus, plus de `uuid`) et aucun `enum`. Surtout, divergences avec le code : `AlertThreshold` expose `minValue`/`maxValue` alors que Prisma a `min`/`max`, et `Measurement.type` n'existe pas dans le modèle.
6. **README — Oui.** Install, Prisma, `npm run dev`, `.env`, liste d'endpoints et exemples curl : on démarre sans contacter l'équipe.
7. **Cohérence endpoints/ressources — Oui.** Nommage singulier uniforme, hiérarchie `building → zone → sensor/actuator/alert-threshold` lisible, pas de doublons ni de routes ambiguës.
8. **Sécurité visible — Non.** Aucun `securitySchemes`, `security` ni route `/auth/*`, alors que toutes les routes métier sont protégées par JWT (sécurité documentée uniquement dans `swagger/v1.ts`, servi à `/docs`).

## Synthèse

- **Point fort :** le nommage des ressources est cohérent — singulier uniforme, hiérarchie claire, pas de routes en double ni de verbes ambigus.
- **Incohérence :** deux contrats coexistent et se contredisent. `openapi.yml` décrit `AlertThreshold` avec `minValue`/`maxValue` et un champ `Measurement.type`, alors que le modèle Prisma (et le spec `swagger/v1.ts` servi à `/docs`) utilisent `min`/`max` et n'ont pas de `type` sur la mesure. Lequel fait foi ?
- **Question :** `openapi.yml` ne documente ni l'authentification JWT (pourtant obligatoire), ni `servers`, ni les routes `/auth/*` — est-ce un contrat partiel, ou doit-il remplacer le spec servi à `/docs` ?
